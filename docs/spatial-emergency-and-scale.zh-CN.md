# 地图、灾害处置与洛杉矶港规模负载补充规范

本补充落实到独立 `codex/fullstack-simulation-demo` 分支；不修改团队旧入口、主分支或 Render 服务。界面使用英文，本文用于中文技术审阅。

## 1. 规模与范围：三种单位必须分开

洛杉矶港官方 2025 全年统计为 **10,239,318.40 TEU**，其中载货进口 5,316,713.30、空箱进口 3,793.15、载货出口 1,429,260.00、空箱出口 3,489,551.95 TEU。七月为 1,019,837.30 TEU。[官方逐月原表](https://portoflosangeles.org/business/statistics/container-statistics/historical-teu-statistics-2025)

- 年度 TEU 是累计货流的标准化单位，不是独立箱号、日库存、同时在场的柜数或每次数据库事件数。
- 年度总量除以 365，是**全年平均日流量**；七月总量除以 31，是**最高月的日平均流量**，不能命名为真实“最繁忙一天”。
- 模拟采用可查看的 20/40 英尺构成假设，才将 TEU 目标转换成合成 movement records；不能把假设的箱型构成写成官方事实。
- 七日负载表示七天模拟货流记录，不代表真实七天的平均堆存时间或同时占用堆场的数量。
- 来源事件频率、码头流量分配、异常比例、停留和服务时间是合成参数。实际业务数据源限制仍为 Terminal49；地图参考与历史文献不被用作实时现场数据。

产品同时保留两个可区分的工作面：精细决策演练用 100 个柜检验独立限制、依赖与资源安排；港口规模负载检验数万至十余万记录的入库、更新、分页、汇总、范围影响和交互。后者不能被宣传为对十余万柜进行全局最优设备排程。

## 2. 真实参考地图与模拟运营图层

真实地理背景来自 OpenStreetMap，保留永久署名，按可见视口加载瓦片，不预取整港或制作离线瓦片包。网络不可用时提示底图缺失，已有参考坐标和运营图层仍可操作。[OSM 瓦片政策](https://operations.osmfoundation.org/policies/tiles/)

七个码头名称与泊位段以[港方目录](https://portoflosangeles.org/business/terminals/container)为依据：APM、Everport、Fenix、TraPac、Yusen、WBCT China Shipping、WBCT LA TiL。位置参考来自 CARB 所存的 2021 年 12 月洛杉矶港 At-Berth Port Plan 第 2 页；点位不是测绘边界、当前卡车闸口或通行路线。WBCT 的历史名称对应尤其注明为近似参考。[原始计划](https://ww2.arb.ca.gov/sites/default/files/2022-05/Los%20Angeles%20-%20Original%20Plan%20%28non-ADA%29.pdf)

精细演练只在 Fenix 参考点附近配置六个**合成逻辑区域**：East/West 闸口、堆场与重量复核、冷藏检查、装船、卸船。其位置、资源、边界与分工不是 Fenix 内部操作图。道路出口与主航道是示意影响线，不提供导航。其他码头没有模型时显示 unknown / N/A，绝不以零表示未知。

港口规模负载启用后，可显示七个码头的合成数据库汇总，必须明确来源为当前 synthetic profile；不能覆盖成真实实时运营状态。地图可关闭、放大、缩小、平移、聚焦码头、选择区域，并把关联货柜带入分页工作列表。

## 3. 状态、进度和数量的含义

| 项目 | 数据与计算 | 不能混用的概念 |
|---|---|---|
| 区域颜色 | 当前确认的模拟事件、区域容量、未解决任务；unknown 单独显示 | 历史事故不是当前预警；未联网不是正常绿色 |
| 实际完成作业 | 模拟执行器中 `status=completed` | 原本已满足的证据条件不算新做了一次检查 |
| 条件满足率 | resolved / 总协调任务，可包括原有合格证据 | 满足率不等于物理吞吐量 |
| 有效提柜 | 本轮合法完成的 gate handoff，每旅程一次 | 已报告离港的历史柜、复称、联系和维护不计 |
| 装船 / 卸船 | 独立合成 workorders 的执行进度与资源时间 | 不将已经卸船的 Terminal49 形状 cohort 再作为新卸船数据 |
| 区域容量 | 分资源类型显示容量、占用、不可用 | 一台地磅和两名工作人员不能相加后叫“三条车道” |
| 港口规模数量 | SQL 汇总的 movements、TEU、阶段和异常 | 不能当真实码头库存或 TOS 执行确认 |

精细船舶模型具有已经靠泊的 A 船、未来到达的 B 船，以及独立 arrival、unload、load、departure 作业。航道阻塞影响未来进出港，不自动暂停已靠泊吊机或卡车。暂停时进度按累计有效服务时间计算，不按墙钟假装继续工作。

## 4. 六类灾害分别提供什么策略

以下是本项目的通用演练策略，参考权威背景与公开规范；不是任何码头批准的应急预案。现场必须遵循雇主应急行动计划和有权限人员的指令。[OSHA 1917.30 应急行动计划](https://www.osha.gov/laws-regs/regulations/standardnumber/1917/1917.30)

| 类别与真实背景 | 调度员先确认 | 系统建议及仍可继续的工作 | 人工升级与恢复证据 |
|---|---|---|---|
| 锂电池货车火灾 / 出入口受阻；LA 2024 | 事故报告、排除范围、道路与码头服务分别是什么状态 | 限制确认受影响的通道；其他独立获准的区域继续；协调预约与冷藏任务但不穿越封控 | 火情、生命安全、范围不清立即交指挥角色；道路开放与码头服务恢复分别确认 |
| 网络 / 数据完整性中断；LA 2017 | 心跳、最老队列、每字段观测和收到时间、完整性报告 | 保留已知扣留、将过期字段标未知；不从断网推导物理停运；仅执行有独立当前许可的任务 | IT 与运营共同接手；去重、字段水位、积压核对和完整性确认后恢复 |
| 强风 / 吊机限制；2023 风暴准备背景及吊机规范 | 设备专用说明、主管确认、具体设备范围 | 停受限吊机，不自动停闸口；分别呈现船舶周转损失和道路工作 | 缺少说明、危险设备状况、矛盾报告交主管；按设备恢复，不用统一猜测风速阈值 |
| 航道阻塞；Baltimore 2024 | 有权限海事限制、船型与通行范围、泊位和陆侧独立状态 | 阻止受限未来 transits；保留待到船舶；已靠泊装卸和陆路独立判断 | 海事/港口主管接手；按许可的船型、单向通行或分段开放恢复 |
| 道路出口拥堵 / 积压；2021 长停留背景 | 下游仓库/道路接收能力、预约、受影响门区 | 匹配下游接收，避免把等待移到门外；显示不同运输组等待与未完成积压 | 回堵影响安全、无接收证据、服务承诺冲突交真人；确认下游容量再分阶段恢复 |
| 地震 / 资产检查；Japan 2011 及 LA 准备原则 | 指挥报告、人员与现场情况、资产检查覆盖 | 限制确认受影响的设备，分开道路、岸壁、航道和公用设施；不能认证未检查资产 | 生命安全、结构疑虑、跨机构/救援优先级需人工；资产逐项确认，不因一个恢复通知全港转绿 |

对应背景来源：

- [LA 港 2024 道路恢复公告](https://portoflosangeles.org/references/2024-news-releases/news_092724_truck_accident)、[LAFD 电池事故记录](https://lafd.org/news/lithiumion-batteries-burn-days-after-san-pedro-big-rig-crash)。不补造实际货损或统一恢复时刻。
- [美国国会议员对 2017 LA 码头关闭的声明](https://torres.house.gov/media-center/press-releases/rep-torres-port-la-terminal-closure-after-cyber-attack)。模型把中断类别移植到模拟场地，不声称事故发生于 Fenix。
- [OSHA 吊机规范](https://www.osha.gov/laws-regs/regulations/standardnumber/1917/1917.45)、[LA Hilary 准备与当时运营信息](https://portoflosangeles.org/references/2023-news-releases/news_081823_hurricane_hilary)。预警与确认停机分开。
- [NTSB Dali 调查](https://www.ntsb.gov/investigations/Pages/DCA24MM031.aspx)、[USACE 航道恢复安排](https://www.nab.usace.army.mil/Media/News-Releases/Article/3731790/us-army-corps-of-engineers-develops-tentative-timeline-to-reopen-fort-mchenry-c/)。不提供航行、救捞或碰撞应急技术指令。
- [LA 2021 积压政策背景](https://portoflosangeles.org/references/2021-news-releases/news_102931_cargofee)。不是实际道路容量、费用始终实施或此模型损失数字的证据。
- [日本 MLIT 2011 港口清障与救援通道记录](https://infra-archive311.thr.mlit.go.jp/en/w02.html)、[LA 应急管理原则](https://portoflosangeles.org/community/residents/emergency-management)。不推测 LA 地震损坏。

## 5. 应急工作流与人工边界

实际工具链为 `observe → impact → retrieve → validate → escalate → track/recover`。当前按用户选择使用规则、来源检索与约束优化，`llm_used=false`；没有伪造模型推理。每一步记录输入、输出、角色、限制、依据与 revision。

1. 当前报告是明确标记的 synthetic incident，而不是从历史文章自动生成实时封路。
2. 范围映射由服务器目录决定。未知范围、未建模范围和不适用组合只监控并升级，不全局改变容量。
3. 历史背景检索与自有处置模板分开；来源文字不被当作系统指令或新增权限。
4. 规则定义不可突破的约束；优化器只安排可执行工作。已知扣留、移动许可和独立证据不会因“很紧急”或工单 resolved 而消失。
5. 创建真实数据库内的协调请求；不发送外部消息。严重程度、证据缺口和角色条件决定交接；未确认超过模拟十分钟提示逾期。十分钟是演练策略，不是行业强制响应 SLA。
6. 接手 acknowledgement 与恢复分开。接手不开放设备；恢复要求明确勾选和人工说明，保留操作者记录。
7. 多事件采用叠加约束：解除事件 A 不得解除仍有效的 B，也不得清除既有现场关闭或来源扣留。

未来接大模型时，只允许根据已给证据产生结构化建议、引用与交接摘要；对工具参数做白名单与 schema 校验，危险权限仍由确定性 guard 与真人决定。当前演示不宣称已验证此未来生成能力。

## 6. 工程验收

地图及灾害验收须验证局部事故不扩散成全港关闭、网络中断不清除扣留、航道关闭不停止已靠泊工作、重叠事故解除不提前开放、未知范围不产生编造数量、warning 不自动关闭，以及恢复后的任务和地图计数一致。

规模验收须保存真实数据库行数、生成参数、精确 TEU 总和、事件数、分页大小、响应耗时、入库/推进耗时、查询计划与错误；至少验证按码头/状态/箱号筛选、重试无重复、重启保留和一页最多 100 条。生成器的速度不等于数据库和界面的速度，必须分别测量。大体量阶段如果采用聚合/简化运营模型，明确说明它不是现场设备执行模型。

性能表和浏览器截图仅在实际运行后填写。真实源可核对的背景、模拟输入、模拟结果、未验证的生产能力必须始终分开。成熟产品功能与内部策略对照见 [成熟方案比较](mature-solution-comparison.zh-CN.md)；逐种子数据见 [仿真评估](simulation-evaluation.zh-CN.md)。
